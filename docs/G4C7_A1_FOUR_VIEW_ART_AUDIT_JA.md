**2026-10-24 JST。これはMinecraft施工版ではない。** ユーザーのG4-C6実機写真から見えた最大の弱点は「32棟がほぼ同じスリムなガラス塔に見えること」と「似た薄い屋根/装飾の反復」。遅さの原因についての実行時間は未計測。従来の全高度Cloneを控える新G4-C7案に対し、まず実施工なしで立体と都市を多方向から審査できる仕組みを作る。

## 追加した成果物

`tools/g4c7_render_review.js --out <NEW_DIRECTORY>` で**新しい出力フォルダー限定**で次のファイルを作る。既存ディレクトリへの上書きは拒否し、Minecraftや旧CSV/ZIP/USEDラッチにはアクセスしない。

- `front.svg`: 前方からの都市シルエット
- `side.svg`: 側方からの高さ関係
- `oblique.svg`: 斜視・屋根・建物の奥行
- `aerial.svg`: 上からの建物数と中庭配置
- `g4c7_review.obj` + `g4c7_review.mtl`: Blenderなどで開ける色分け済みの概念立方体メッシュ（Y-up、1単位=1ブロック）。これはプロシージャルなMinecraft施工メッシュではなく、22棟のブロック形状だけを6面化した試作データ。
- `review_quality.json`: 4地区ごとの平面形反復数と品質ゲート
- `source_geometry.json`: 全box/部材・寸法を独立確認できるJSON

GitHub Actionsはこれらを`g4c7-a1-fourview-svg-obj-quality-concept-only`として保存する。SVGはフォトリアルなMinecraft実景写真でも、実物の当たり判定再現でもない。地表道路の道路面・植栽などは簡略表示であり、無いからといって都市が施工済みである/ないとは判定しない。

## 新規の根本改善

初回A0コンセプトは4地区の種類が異なるにも関わらず、**各地区内の建物が基本的に同一の平面形を高さ違い・塗装違いで繰り返していた**。このまま実機施工しても「街並みが単調」が再発する。

A1では22棟それぞれに敷地の幅・奥行・壁の太さ・中庭の開く方向・支柱間隔・塔頂のセットバック・研究棟の橋の長さに異なるプランを与えた。例：
- A 金融：4棟の高層コアは各々異なる太さ、奥行、段差。2低層ポディウムも別形状。
- B 文化：5棟の平面スパンと屋根・柱位置を変え、2棟には低層入口ボリュームを統合。
- C 住宅：6棟のU字中庭棟の中庭の幅/向き（南北の開放）・壁厚が異なる。単に同じU字の色を替えない。
- D 研究：5棟の横方向の深さ、ラボ間隔、連絡ギャラリー幅を変えた。

`assess(plan)`は材質と高さだけの差分を除外して、**平面配置と用途部材から構造的な輪郭を比較**する。各地区少なくとも3種類以上の異なる構成を要求し、同形3棟以上の反復を不合格にする。これに合格しても「現物の建築としてセンスがある」ことを証明しないので最終評価は`REQUIRES_HUMAN_ART_REVIEW`（人間の美術審査待ち）。

## 引き続きチェックすべき美術課題

1. B文化地区は平面が変化しても**薄板状の大屋根**が残るリスクが高い。支持の数・高さだけでなく、低層文化施設として見える面と入口を要審査。
2. D研究地区は箱の間にガラス橋を載せただけに見える恐れがある。主室・研究室・橋の空間的つながりを将来の施工モデルで証明する。
3. C住宅地区の中庭は形だけでなく、住民が入口から中庭へ出られ、2階以上へ登れることが必要。
4. A都心は高層だけでなく道路や広場沿いの低層商業の表現が必要。
5. 旧G4C6の浮遊フレーム・巨大冠・道路パターンを無批判にコピーしない。新案にはそもそもその装飾を含めていないが、これだけでは文化的な個性や公共施設が十分とは言えない。
