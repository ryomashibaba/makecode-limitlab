## 写真からソースまで確認できた具体的問題
- Finance A地区の公共門柱は `g4c2OverlayAdd(0,86,27,86,3,26,3,...)` と `(0,104,27,86,3,26,3,...)` で施工されていた。広場の歩行可能な床Y1から**26ブロック上**を始点としていたことが不自然な浮遊表現の原因として強く疑われる。既存中央モニュメントと門柱は別の位置にあるため、直接つながっているとは扱えない。
- B文化地区の大きな板屋根とC居住地区の屋上庭園は施工自体はPASSしたが、写真では支持構造の見え方が弱い。Y1の既存歩行空間を損ねず、既存ビル本体に外装リブを接合する。

## A2-A2実装（専用新規ソース、旧A2-A1不変）
- `makecode/limitlab_g4c3_a2.ts` に同じ4地区・372×372・実機PASSした5+44=49 Cloneの複製順序を維持。
- A地区の公共フレーム2本の脚を**Y2..52まで下ろす**。最上部のシアン色梁は同じY51..52で接合し、下のY1広場床とも接触させる。
- B文化地区には2棟に合計**4本の白い支持リブ**（Y14..60およびY14..64）を設置。いずれも屋根下面に接し、実体的な外壁から大屋根へ形態が連続する。
- C居住緑化地区は3か所の庭園屋根へ合計**6本の大型白色支持リブ**を取り付ける。Y+1の歩道や道路には一切書き込まず、建物の上層壁から屋上庭園の下面に接触する。
- 計10 Fillを追加し、`A2_OVERLAY=61`、**総Fill 447 / Clone 49**。全Fill最大32768、全Clone最大262144、都市範囲X/Z0..371・Y0..83は不変。追加造形はY>=2。

- コマンドは独立 `labcityg4c3`、`labareag4c3`、`labstatusg4c3`、`labstopg4c3`。独立ラッチ`G4C3_ONCE.txt`、CSV`USER_UPLOAD_THIS_G4C3_STATUS.csv`、`RUN_G4C3_A2.cmd`。以前の実機ラッチ/CSVを一切触らない。

## 合否と速度
- オフラインの実行可能ボクセルモデルでは、A公共脚の地表から梁までの連続性、B・Cの屋根リブと屋根下面の接触、Y1道路の全4地区同一性、建築上部の地区差、事前AIR空間検査・USEDラッチの拒否・失敗時STOPを検査する。
- Linux/Windows CIが完全PASSするまで実機実行を案内しない。PASS後も**新しい破棄可能テストワールド限定**で一度だけ新施工する。RUN重複・旧ZIPの消去・既存ワールドへの上書きを禁止。
- 最終的な美術合否は、ユーザーの俯瞰＋地上スクリーンショットを前回A2-A1と比較して判断。支持リブが太すぎて建築の美しさを損なう場合は再修正する。
- この10 Fill差分は大規模な建築反復感を完全に消す対策ではない。A2-A3では地区の建物本体の形態差、公共施設の利用機能、低層/中層の構成を重視。写真上の仮説を完全一致・接続性証明と扱わない。
