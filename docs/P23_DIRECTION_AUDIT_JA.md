# MakeCode LimitLab P2.3 — 方針・計画・効率監査

## 結論
**方針は維持。** ただしP2.0までの「単一命令の最大サイズ」研究、P2.1の「細分化しすぎた汎用施工」、P2.2の「FASTで事前計算」、P2.2.1の「応答性の改善」を踏まえ、P2.3は**実際に都市を生成する研究の最初の完成可能な工程**と位置づける。

| 評価項目 | 判定 | 根拠 |
| --- | --- | --- |
| 本来の目標 | PASS | MakeCodeの限界を利用した巨大都市を生成するため、道路・街区・建物・公共空間の設計と施工に着手 |
| 計画の連続性 | PASS | P2.2.1の`FAST_COMPLETED_SAMPLED`実機完走、約1〜2分の体感実行時間を基準情報として扱う |
| 効率 | 改善を追求 | 事前計算した大きなfillで道路・塔の構造を生成し、独立した3種の建物を5回のcloneで他の街区へ展開。毎ブロック検査や頻繁なファイル保存へ戻らない |
| 品質・見た目 | 開発余地あり | 3種類の高さ・フレーム・セットバック・中央広場を作るが、STONE/GOLD/AIRの2色造形は最終景観でない |
| 安全性 | 条件付き | 破棄可能なワールドでのみ施工。75点の疎なAIR検査は建築物の重複を完全に防がない |
| 正確な実績表示 | PASS | FASTはサンプル検査しか実施しない。実機CSVで完了するまではP2.3の施工成功を断言しない |
| ユーザーの操作量 | 最小化 | 1回のコードコピー、read-only場所表示、1回の施工命令、結果CSVを1回共有 |
| 古い成果の保全 | PASS | P1.0〜P2.2.1を編集せず、P23専用のコピー補助・ラッチ・CSVを追加 |

## 次工程の優先順位（P2.3実機成功後）

1. **道路／街区／8棟の3D景観と中央広場を確認**：成功しても見た目が低品質なら、形状／配色／窓表現を修正。無理に都市を巨大化しない。
2. **P2.4の都市モジュール拡張**：建物・道路・公共広場をデータ化し、異なる街区・道路幅・高さの都市設計を生成できるようにする。
3. **材料パレットの実機互換テスト**：ガラス・コンクリート・発光ブロックなどを導入する前に、MakeCode Educationでの正確なブロック指定方法を調査する。
4. **速度が悪化した場合**：少数の建築モジュールの複製・大量の矩形コマンド・チャンク読み込みを切り分け、測定してから最適化。長時間の待機・全域検査は標準に戻さない。

**停止条件**：予期せぬ書込み、開始時の無応答、clone false、代表点の不一致、重複する施工領域が認められた場合は停止。再実行・自動削除は行わない。
