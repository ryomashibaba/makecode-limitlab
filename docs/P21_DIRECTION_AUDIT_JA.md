# P2.1 方針・計画・効率監査（2026-10-18）

**判断：P2.0の実機ALL_PASSを根拠に、最大値探査から実用的な分割施工・複製・変更へ移行する。P2.1の実機成功は未確認。**

## 根拠と証拠の区別

- ユーザー提供P2.0 CSVを読み取り、196,608と262,144の単一clone全域PASS、RESET PASS、RUN FINISHED ALL_PASSを確認。個人CSV・実座標・ワールドは公開しない。
- P2.0以前のソースはそのまま保持し、P2.1追加時の11ソースの検査値で継続確認する。
- P2.1の模擬試験とCIは開発検証。Minecraft Education本体のAPI・拡張・チャンク・端末性能を再現したとは扱わない。

## 方針

単一cloneの実測262,144をさらに拡大する試験は行わない。大規模な非均一建築を、十分小さい命令へ分割し、全域一致を確かめてから次へ進める。部分変更は変更対象だけの検証で済ませず、変更しない領域とコピー元も全域確認する。

ワールドの自動判別はできないため、破棄可能な専用ワールドの選択はユーザーの実機手順で明示する。開発中はMinecraftを操作しない。Chat主体の方針を維持し、今回のCodex／Work実装・PR・CIは事前相談後のユーザー了承を受けて行う。この了承を今後のWork利用全般へ拡張しない。

## 計画と合否ゲート

計画の妥当性 → 永続一回記録 → CSV保存確認 → 全域AIR → 参照作成検証 → 分割施工と全域照合 → 分割cloneと全域照合 → 変更直前の全域照合 → 部分変更と全域照合 → 終了行・チャット。

最初の異常または停止で後続施工を止める。fail-closedは失敗後に元へ戻す意味ではなく、未確認状態に追加の変更を重ねない意味である。施工済み領域と失敗途中の状態は残し、診断に使う。

## 効率

## 残る制約と次の判断

- 汎用化は、設定可能な寸法・分割・タイル材質関数・立方体変更に限定。任意構造物のインポートやブロック状態保存は未対応。
- 実機結果が出るまで、速度改善・規模拡大・連続耐久を同時追加しない。既存のfill境界、I/O、耐久の研究成果は保持する。
- P2.1 ALL_PASSなら、CSVの工程・境界・最終全域照合を確認してから次の用途を選ぶ。STOP／未完了なら原因診断を優先し、再試行を促さない。
- APIハング・未読込み・同時編集・周囲8ブロック外の副作用・ユーザーによる一回記録の削除には限界がある。CI成功をもってこれらの実機安全性を証明しない。
