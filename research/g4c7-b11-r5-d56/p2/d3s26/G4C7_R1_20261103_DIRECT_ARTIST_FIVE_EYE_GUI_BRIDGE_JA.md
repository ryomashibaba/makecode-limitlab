## 判定

**コード実装済み／Blender実GUIでの実使用は未実証／新しい都市の美術成果0。** これはコード式都市生成の第三案でも、空のBlenderスモークテストの追加でもない。全体ART HOLD・正式美術採用0件。R0〜R5不変。

## 実際に見つけた作業障害

従来の [直接作者Blenderスタジオ](../../../../tools/g4c7_m37p2_direct_author_studio.py) と [ワンファイルGUIレビュー](../../../../tools/g4c7_m37p2_one_file_early_art_review_gui.py) は **AERIAL / PUBLIC_EYE / HABITAT_EYEの3カメラ構成**と3視点レビューを前提にしている。

一方、2026年11月3日の [2案不採用後の作者ブリーフ](G4C7_R1_20261103_POST_TWO_REJECTS_DIRECT_ARTIST_BRIEF_RESET_JA.md) と [最新のR1直接作者契約](G4C7_R1_20261103_DIRECT_ARTIST_INTAKE_CONTRACT.json) は **AERIAL / PUBLIC_EYE / HABITAT_EYE / FACTORY_EYE / RESEARCH_EYEの5真正視点**、同一保存原本、工場製造と研究の実利用を必須とする。このままでは作者が新しい建築を制作しても、新要求の視点取得を古いGUIのワンファイル操作だけでは完了できない。

## 今工程の実装

[独立した5視点直接作者ブリッジ](../../../../tools/g4c7_r1_five_eye_direct_artist_bridge.py) を追加した。既存v3原本と従来3視点GUIは**不変更**。本体は3D都市/箱/壁/メッシュを一切生成しない。

- **新しい別名で保存した作者用BLENDだけ**を対象とする。保護v3のアーカイブ実名、既存Civic Estuary/Civic Braid不採用原本は拒否。研究憲章 ART HOLD／正式採用0／331/993 NOT RUN／Minecraft FORBIDDEN／旧不採用形態を持ち込まない、を検査。
- 既存3カメラを尊重し、**FACTORY_EYE と RESEARCH_EYE の不足2カメラだけ暫定追加**する。建築メッシュ0個追加。作者がBlenderの実ビューポートを移動した構図を、選択した視点カメラへ反映できる。作者自身の確認状態は写真の美術品質を保証しない。
- 5領域（都市全景、生活断面、工場境界、研究文化、住宅私界）に**作者が直接造形した非空メッシュが必要**。同じオブジェクトを何度も置いた品質の代替指標にはしない。「全景と生活断面を同時造形した」という作者宣言を要求するが、宣言だけでは証明できないことを区別。
- GUIで新原本を **Save Asで別名保存**した後、**同じファイルを独立Blenderバックグラウンドプロセスで再読込して5真正Cycles画像を一括生成**するボタンを実装。新規の別レビュー出力ディレクトリにPNG・原本SHA256・画像ごとのSHA256とカメラ情報・ART HOLDのJSONを書き、BLENDを書き戻さない。出力先の上書き拒否。
- GUIを実際に操作して見栄えを理解する高度な作者能力・芸術センスを追加したわけではない。未確認の案に美術資格を与えない。

[Pure Python負例テスト](../../../../tests/test_g4c7_r1_five_eye_direct_artist_bridge.py) と [軽量GitHub CI](../../../../.github/workflows/g4c7-r1-five-eye-direct-artist-bridge.yml) は、5役割、原本保護、定款改変拒否、不採用形態混入の拒否、空原本のレビュー拒否、BLEND実レンダの別プロセス限定を静的に確認する。**Blender自体やGUIを動かすCIではなく、実ネイティブ結果についてPASSとは書かない**。

## 将来の使い方（現時点でユーザーの操作・費用を要求しない）

新しい建築を作る本当の作者がBlenderを使える状況で、保護v3そのものではなく**別名の新しい作業コピー**を開き、このPythonをBlenderアドオンとして導入し、必要カメラを補ってから、実景を見ながら全景と生活断面を直接造形する。5視点を作者自身が構図確認し、新しいBLENDに保存したうえで、アドオンの「Reopen saved native; render all 5 eyes」を使う。

プラグインの実GUI使用と、5本のCycles保存画像が**本物の新規作者3D**で成立するまでは、SOURCE-only準備と記録する。既存の空v3やSuzanneだけで「新しい作者能力が証明された」とは呼ばない。ユーザーに毎回ローカル実行・スクリーンショットを依頼しない。Workや高額モデルを利用するには、既存方針どおり事前の明示承認が必要。

## 残る本質的障害

**直接作者の高品質Blender造形能力は依然未成立。** 本工程のUI橋渡しは、3視点→5視点の移行で発生する手動の作業ミスを減らすための道具であり、世界的な未来都市作品を新しく作り出さない。GitHub Actionsで旧箱型・低密度キャンパスを再生成することも禁止。真の制作へ進むには建築美術を判断しながら保存ネイティブを編集できる作者主体が必要。Work等によるクラウドGUI利用可否・品質・追加費用は事前承認と実証が必要。
