# LimitLab P2.1 — 汎用分割施工・clone・全域検証・部分変更

**P2.1はMinecraft Education実機未検証です。CIと模擬試験の成功を、実機成功とは扱いません。**

P2.0のユーザー提供CSVでは、単一clone 196,608・262,144が全域一致し、最終結果ALL_PASSを確認しました。個人CSVは公開しません。この実績はその環境・形状での成功記録であり、普遍的なAPI上限ではありません。

P2.1は最大値更新を止め、異なる材質・AIR内部・端数寸法を含む巨大建築の施工、分割複製、部分変更を研究します。過去版のソースは変更しません。

## 既定の一回試験

| 工程 | 内容 | 合格条件 |
| --- | --- | --- |
| 計画検査 | 82×49×77＝309,386ブロック／領域 | 寸法・分割・変更範囲が安全境界内 |
| 全域AIR検査 | コピー元・複製先・各周囲8ブロック・3参照キューブ。最大6候補 | 全対象がAIR。falseや未読込みを空きと解釈しない |
| 参照作成 | AIR／STONE／GOLD、各8³ | 参照の全セルを個別検証 |
| SOURCE | 床・外殻・柱・空洞を持つ770タイル。端タイルは切詰め | 一fill最大512。コピー元全域一致・複製先AIR・周囲AIR |
| CLONE | 32×16×32以下に分割し36命令 | 各cloneのtrueと対象全域一致。参照・周囲も検査。最後に両領域全域照合 |
| BEFORE_PATCH | 両領域全域を再照合 | 変更前の状態が完全一致 |
| PATCH | 複製先の(16,16,16)から16³をGOLDに変更、512×8命令 | 変更範囲を含む複製先全域、元のコピー元全域、参照、周囲が一致 |
| 終了 | CSV保存・読戻し・Minecraftチャット | TEST FINISHED / ALL_PASS、またはTEST STOPPEDと理由 |

全域検証とは、この表のコピー元・複製先・参照・周囲の有限範囲です。ワールド全体を走査する意味ではありません。参照作成は2回のfillを使います。SOURCEのAIRタイルには書込みません。

## Windowsでの準備と実機操作

1. この版を含むGitHubのZIPを取得・解凍し、`makecode/COPY_P21.cmd` を実行。**COPY OK**を確認します。
2. Minecraft Educationの**破棄可能なLimitLab専用ワールド**を開きます。重要ワールドやMinecraftAIBuilderでは実行しません。事前にワールドを目視確認してください。コードはワールド名・用途を自動判定できません。
3. MakeCode JavaScriptに貼付け、既存のFile Read & Write拡張を維持。エラー0件を確認して再生します。
4. Minecraftチャットで **`labauto21`を1回だけ**入力します。
5. `TEST FINISHED`または`TEST STOPPED`を待ち、`Downloads/MakeCode_LimitLab/results/USER_UPLOAD_THIS_P21_STATUS.csv`をChatへ提出します。失敗後に再実行しません。

補助コマンド：`labstatus21`（進捗）、`labreport21`（結果再表示）、`labplan21`（計画表示）、`labstop21`（協調停止）。結果表示コマンドはワールドもCSVも変更しません。

ヘルパーは初回だけ`logs/P21_ONCE.txt`へ`READY_P21`を用意します。実行開始時に`USED_P21`へ保存・読戻ししてから先へ進みます。ヘルパーの再実行でもリセットせず、MakeCode再読込み後も再施工を拒否します。同じ出力フォルダーを使ってください。記録を削除・編集したり、別フォルダーを使えば保護を迂回できるため、操作しないでください。

CSV保存後は毎回読戻して一致を確認します。失敗したら後続施工を止め、チャットでCSV保存失敗を知らせます。元のCSVが残る場合はそのまま保持してください。

## 汎用化の範囲

`limitlab_p2_1.ts`冒頭で幅・高さ・奥行、clone分割、変更範囲を設定できます。各寸法32〜96、全体600,000以下、clone各辺8の倍数で32以下・体積16,384以下、変更立方体の辺8〜32で8の倍数・原点8の倍数・全体内に制限します。端数寸法は切詰め、隙間や重複なく全域を処理します。

建築内容は`p21Material`が決める8³単位の材質関数です。任意の既存建築・外部schematic・向き付きブロック・ブロック状態を取り込む機能は未実装です。材質関数や定数を変更した場合は、ヘルパーのソース検査値とテストも更新する必要があります。出荷状態の設定から無検証で拡大しないでください。

## 安全性と限界

- 最初の施工前に全書込み領域をAIR確認し、その後も施工直前の対象を確認します。座標の異なる候補へ移るのは書込み前だけです。
- clone失敗・falseなのに全域一致・不一致・CSV読戻し失敗・停止要求は後続工程へ進めません。失敗後の自動消去・巻戻し・再試行はありません。自分が施工した部分も残します。
- 試験中はプレイヤーやほかのプログラムで検査対象を編集しないでください。検査と書込みの間の同時変更、遠方未読込み、APIの範囲外副作用までは完全に防げません。周囲8ブロックより外の破壊を検出したとは主張しません。
- ネイティブAPIがハングする、MakeCodeが終了する、ファイルAPIが例外で停止する場合、スクリプトによる強制キャンセル・最終CSV・終了通知を保証できません。終了行がないCSVは未完了です。
- 停止は安全チェック地点で協調的に処理します。耐久待機や既知の単一clone最大値の再試験は入れません。

## 開発検証

GitHub Actionsの`Verify LimitLab P2.1`で、固定版TypeScriptと既存APIスタブによるコンパイル、独立ボクセル期待値と異常注入、厳密CSV解釈、旧ソース保持、P2.0回帰、Windows PowerShell 5.1準備・一回記録保持を検証します。APIスタブでのコンパイルはMakeCode本体での受入れ確認を代替しません。

CSVのローカル診断：`python tools/analyze_p21.py <CSVパス>`。この判定はCSVの整合性検査であり、CSVの実機由来を証明するものではありません。個人CSVやワールドデータをGitHubへコミットしません。
