# MakeCode LimitLab P1.7 — 1命令の境界調査と明確な終了通知

## 今回の目的

P1.6では、Minecraft Education実機で **65,536ブロックの分割施工・複製** と、**32,768ブロックの単一`fill`・単一`clone`** がPASSしました。P1.7はこの結果を出発点に、単一命令の境界直上を調べます。以前の「長時間待機だけの耐久ループ」は行いません。

**今回の試験サイズは 32,800（+32）→ 33,024（+256）ブロックです。** 32,769ちょうどをコンパクトな直方体で扱うと一辺が非常に長くなり、チャンク読み込みなど実験以外の要因を増やすため、近傍のコンパクトな寸法を選びました。

| 検証 | 体積 | 座標上の寸法 |
|---|---:|---|
| 第1段階 | 32,800 | 20×40×41 |
| 第2段階 | 33,024 | 24×32×43 |

両方のAPIが第1段階でPASSした場合だけ、第2段階へ進みます。第1段階で`fill`が失敗しても、同じ大きさの`clone`は独立して試します。失敗した同じ命令を自動で再試行しません。

## 終了がひと目でわかるようになりました

Minecraftのチャットに、開始時は `===== BOUNDARY STUDY START =====`、最後に以下のように**目立つメッセージを3行**表示します。

```text
LimitLab P1.7 ========== TEST FINISHED ==========
LimitLab P1.7 Result PASS: BOTH_SINGLE_33024_EXACT_NOT_TRUE_MAX
LimitLab P1.7 Send USER_UPLOAD_THIS_P17_STATUS.csv
```

境界で書き込み失敗を確認した場合でも、**それが正常に診断・記録できたなら**`TEST FINISHED`と`Result LIMIT`を表示します。故障・占有・手動停止の場合は`========== TEST STOPPED ==========`を表示します。

**例外**：MinecraftのAPI自体が内部でフリーズしたり実行スレッドが強制終了する場合、コード側から終了表示を保証できません。この場合は`labstatus17`とCSV最後のBEGIN行を使って確認します。

## 施工内容と安全性

- **使い捨てのLimitLab専用テストワールド以外では実行しないこと。** P1.6の以前の建物は削除しません。
- 事前検査：元構造、fill先、clone先の最大それぞれ **24×40×43=41,280ブロック**（合計123,840ブロック）と、空気基準8×8×8を2つ検査します。最大3候補を調べ、すべて空なら施工開始。占有されている場合は建築せず停止します。
- 元構造：GOLD_BLOCKで24×40×43を最大768ブロック/命令の小分けで作成し、参照キューブと全タイルを照合します。
- 各サイズで`blocks.fill`と`blocks.clone`を**それぞれ一度だけ**呼び、全領域の512ブロック以下のタイルを比較します。
- 不一致時は、参照AIRとの比較も行い、**全く書かれていない`NO_WRITE`と、一部/異物が残った`PARTIAL_OR_WRONG_BLOCKS`を区別**します。これは原因の分類であり、失敗した命令が何ブロック更新したかの正確な個数測定ではありません。
- 第2段階に進む前には、**P1.7自身が作った2つの施工先のみ**を小分けにAIRで初期化し、再検証します。元構造物は維持します。
- 停止要求に応答する`loops.pause(1)`の短いポイントのみを設け、長時間の耐久待機は追加しません。実時間を保証するものではありません。

## あなたの操作

1. [GitHub mainのZIP](https://github.com/ryomashibaba/makecode-limitlab/archive/refs/heads/main.zip) を解凍し、`makecode/COPY_P17.cmd`をダブルクリックする。`COPY OK`を確認してください。失敗した場合は準備された`PASTE_THIS_P17.ts`を使います。
2. Minecraft EducationのMakeCode JavaScript欄に貼り付けます。**File Read & Write拡張機能**を維持し、エラー0件を確認して再生します。
3. **使い捨てのLimitLab専用ワールド**で`labauto17`を**1回だけ**実行します。32,800と33,024の実験が順に動きます。
4. Minecraftチャットの **`TEST FINISHED` または `TEST STOPPED`** を確認し、`Downloads\MakeCode_LimitLab\results\USER_UPLOAD_THIS_P17_STATUS.csv`をアップロードしてください。

ほかのチャットコマンド：

- `labstatus17`：現在のステージ、進行状況、終了状態を表示。
- `labstop17`：停止要求。次の安全チェックポイントで停止します。大きな1命令の実行中に強制中断できる保証はありません。
- `labplan17`：読み取り専用のサイズと注意事項。
- `labauto17`：一度しか実行できず、再試行すると拒否します。

## 成果の読み方

- `PASS`：試験した大きさを1命令で実行し、参照ブロックとの全域一致を確認。
- `LIMIT`：要求した大きさでは正しく完了していない（0ブロック／部分施工／返り値falseなど）。**Minecraft APIの普遍的な最大上限を断定するものではありません。**
- `STOP`：安全条件不成立・ユーザー停止・ソース構築エラーなどにより中断。再施工は禁止。
- 正常完了時も限界検出時も、直前の検証済みP1.6の32,768ブロック実績は取り消しません。

実機試験成功の判定は**ユーザーから送られたCSVとチャット表示**を使います。CIによるTypeScript・Node模擬・Python解析のPASSは、Minecraft実機PASSではありません。
