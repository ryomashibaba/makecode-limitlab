# MakeCode LimitLab P2.2 — 高速施工・検証分離エンジン

**P2.2のMinecraft Education実機動作は未検証です。** GitHub CIの模擬成功を実機成功と呼ばないでください。

## なぜこの変更が必要なのか

P2.1の実機試験では、309,386ブロック相当のSOURCE対象領域を施工・全域検証してPASSしましたが、分割cloneが9/36の時点で非常に時間がかかり、ユーザーが停止しました。CSVの最終結果はSTOP / USER_STOPで、実機ALL PASSではありません。

原因の候補はP2.1の多数の小分けfill、タイルごとの事前・事後照合、36回のcloneとその検査、大量のCSV書込み・読戻しです。個別処理の実時間を測っていないため、**どれが最大のボトルネックかは未確定**です。

本プロジェクトの主目的はMinecraft Education MakeCodeの実際の能力を測定し、将来的に**数百万〜数千万ブロック級の巨大都市を高速かつ正確に生成する基盤**を作ることです。P2.2では設計を変え、全域照合を日常施工の必須条件から外します。

## P2.2のFASTとVERIFY

| 機能 | FAST（推奨初回） | VERIFY（詳細検証が必要なときのみ） |
| --- | --- | --- |
| 施工計画 | 全座標をメモリで事前計算・重複なしの領域に結合 | 同左 |
| ワールドの事前AIR検査 | **少数の代表点と周辺点だけ** | FASTと同じ事前検査 |
| SOURCE施工 | 同じ建築モデルの結合fill（最大32,768／命令） | 同左 |
| clone | 成功実績のある262,144以下の大型命令へ分割 | 同左 |
| PATCH | 16×16×16を一命令のfillで変更 | 同左 |
| 実行途中の検査 | 代表点のみ＋clone返り値 | 同左 |
| 最終検査 | 代表点のみ | **コピー元・変更後の複製先全タイルを8³参照と一致照合** |
| 成功時の結果名 | `FAST_COMPLETED_SAMPLED` | `VERIFY_PASS_EXACT` |

重要：**FASTの完了は全域一致を証明しません。** 少数の代表点に現れない誤施工や既存ブロックの上書きは見逃す可能性があります。詳細な品質保証が必要な試験はVERIFYモードを選んでください。

## 事前計算と命令数

既定のSOURCE／複製先モデルはP2.1と同じ**82×49×77＝309,386ブロック／領域**です。床、外壁、柱、空気の内部空間、16³の部分変更を含みます。

- P2.1のSOURCEは8³タイルを基準に約572回の施工前CSV記録を残しました。
- P2.2は**空間的に隣接する同材質のタイルを3次元でまとめる計算**をMinecraftへの書込み前にすべて行います。最大32,768ブロック以下のfillへ安全に分割し、非AIR領域の体積合計とタイル被覆を検算します。**既定モデルのオフライン検証ではSOURCEのfillは68回、非AIR施工体積は208,010ブロック**です（部分変更fillを加えるとFASTのfill計69回）。P2.1のSOURCE施工前CSV記録約572件と比較して、施工命令数を約88%削減する設計です。これは命令数の比較であり、実際の施工時間が88%短縮するとの意味ではありません。
- P2.1のclone36命令から、既定P2.2では**40層＋9層の2命令**へ集約します（252,560＋56,826ブロック）。どちらもP2.0で成功確認した262,144ブロック以下です。ただしP2.0で複製したのは一様GOLDであり、異なるブロックを含むP2.2の複製能力は**別途実機確認が必要**です。
- 部分変更は16³＝4,096ブロックのfill **1命令**。
- CSVは工程開始・完了・一定間隔の進捗だけを書き、重要な行で読み戻します。タイル・命令ごとの常時ファイル書込みはしません。

**今後の汎用都市計画にも使えるよう、同じ領域分割・結合の考え方を維持**します。ただしP2.2は既定の材質関数を対象とした研究段階です。schematic読込み、座標変換、多種類のブロック状態の復元、都市全体の自動配置は未実装です。

## 安全性 — 特に重要

**FASTは新しく作った破棄可能なLimitLab専用ワールドでのみ実行してください。** 空の上空に約2×309,386ブロックのコピー元・複製先領域を確保している前提です。既存のP2.1施工物が残ったワールドには使わないでください。

- FASTは全領域のAIR事前検査を**意図的に省略**しています。代表点がAIRでも周囲の別のブロックが存在する可能性があります。既存建築や重要ワールドでの使用は禁止です。
- コードはユーザーが専用ワールドを開いているか自動判定できません。上書きしてよい使い捨てワールドか本人が確認する必要があります。
- 施工計画は全命令の座標・重複・体積をオフライン計算し、32,768を超えるfillや262,144を超えるcloneは発行しません。
- 異常時は後続を停止。ネイティブのcloneがfalseを返した場合やサンプル検査不一致、CSV読戻し失敗は続行しません。失敗時の自動削除、巻戻し、再実行はありません。
- MakeCodeのAPI呼び出し自体がハングした場合は、強制停止も最終メッセージも保証できません。
- 検査精度を上げるVERIFYも、初回の事前AIR検査まではFASTと同じです。**重要ワールドの既存建築を保護するモードではありません。**
- 永続的な一回限りのラッチ`P22_ONCE.txt`はP2.1と別で、使い切った後はCOPY補助を再実行しても解除されません。CSVは保持してください。
- 実測CSV・ワールド・スクリーンショット・個人PCログは公開GitHubにアップロードしません。

## WindowsとMinecraftでの操作

1. [GitHub mainの最新版ZIP](https://github.com/ryomashibaba/makecode-limitlab/archive/refs/heads/main.zip)を解凍し、`makecode/COPY_P22.cmd`を実行して`COPY OK`を確認してください。
2. Minecraft Educationで**新規の破棄可能なLimitLab専用ワールド**を開きます。以前のP2.1試験ワールドには戻らないでください。
3. MakeCodeのJavaScript欄へ`Ctrl+A`→`Ctrl+V`で貼付け、**File Read & Write拡張機能**を維持し、エラー0件で再生します。
4. Minecraftチャットに次のいずれかを**一度だけ**入力してください。

   - **`labfast22`**：速度優先。サンプル確認のみ。通常はこちらを推奨。
   - **`labverify22`**：同じ施工を実施後、コピー元・複製先の完全一致を全タイル確認。長時間かかる可能性あり。

5. `========== TEST FINISHED ==========`／`========== TEST STOPPED ==========`の表示後、`Downloads\MakeCode_LimitLab\results\USER_UPLOAD_THIS_P22_STATUS.csv`をChatGPTへ送ってください。

その他：`labstatus22`で工程・進捗表示、`labreport22`で結果のみ再表示、`labstop22`で協調停止、`labplan22`で設計表示。これらは施工を始めません。

**モードの切替や同じ世界での再試行は禁止です。** 一回試験したワールド・一回使ったラッチを再利用しないでください。

## 成功判定の違い

FASTが終わったら `FAST_COMPLETED_SAMPLED` と表示します。これは工程完走と代表点チェックの成功であり、**完全施工成功の証明ではありません**。

VERIFYが終わったら `VERIFY_PASS_EXACT` と表示し、今回のモデルのコピー元・PATCH後複製先の全タイル一致が得られたことを示します。ただしMinecraft内で測定可能な範囲に限られ、ワールド全域や無制限の他の建築への正しさを保証しません。
