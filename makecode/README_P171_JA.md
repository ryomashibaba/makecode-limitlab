# MakeCode LimitLab P1.7.1 — 安全候補の探索改善（P1.7ホットフィックス）

**この修正はP1.7の実機成功を消したり、既存の施工物を触ったりしません。今すぐ再実行する必要はありません。**

## P1.7実機の確定情報

- 最初の場所ではP1.7の安全検査で全3候補が不合格。施工は開始されなかった。
- ユーザーが場所を変えた再試験では、**候補1のPREFLIGHTがPASS**、41,280ブロックのGOLDソース構築・完全照合がPASS。
- **単一fill 32,800ブロック: LIMIT/NO_WRITE**（施工後もAIRのまま）。
- **単一clone 32,800ブロック: PASS/全域一致**。
- 33,024ブロックの試験には進んでいない。
- P1.6の単一fill/clone各32,768ブロックPASSは引き続き有効。以上から「今回の形状・条件ではfill 32,800で不成功、cloneは成功」。Minecraft APIの絶対的な最大値とは断定しない。

## P1.7.1で直したこと

P1.7は、元のプレイヤー位置からZ方向に54ブロックずつ離した3候補を調べていたため、既存の大きな構造物が近くにあると連続して失敗しやすかった。

P1.7.1は**候補をX・Z両方向に離した6地点に変更**。各候補は書き込み可能な3つの領域（SOURCE / FILL / CLONE、各最大41,280ブロック）と、2つのAIR参照領域の空気確認が成功したときだけ採用する。

- 1番目は旧P1.7と同じ座標。空いていれば追加の候補探索はしない。
- 2〜6番目はプレイヤー相対でX・Zを別方向に移動。横方向にも逃げるため、隣の建物との重複を避けやすくした。
- 候補が不合格の場合、CSVに `PREFLIGHT,候補番号,6,SKIP,...` を記録。SOURCE/FILL/CLONE/REFERENCEのどこが不合格だったか、最初のタイルの相対座標を記録する。
- 不合格判定は**非AIRか確認不可か**を完全には区別できない。未読み込み領域を「安全」と保証できる新APIは追加されていないため、Minecraftの実際のチャンク状態によっては使い捨てワールド内でも判定が不確実な場合がある。怪しい場合は手動停止して結果を共有する。
- **6候補全部不合格なら1ブロックも書かずSTOP**。さらに広げ続ける無制限探索や自動施工は行わない。

安全チェックのハードル、1命令32800/33024の閾値試験、結果の全数照合、失敗後の再試行禁止、`TEST FINISHED` / `TEST STOPPED` の表示は維持。

## 必要になったときだけ実行する手順

1. [GitHubの最新版ZIP](https://github.com/ryomashibaba/makecode-limitlab/archive/refs/heads/main.zip)を解凍し、`makecode/COPY_P171.cmd`を実行。`COPY OK`を確認。
2. MakeCode JavaScript欄へ貼り付け、File Read & Write拡張機能を維持、エラー0件で再生。
3. **破棄可能なLimitLab専用ワールドで**`labauto171`を一度だけ実行。既存のP1.7実験を同じ場所で上書きしないこと。
4. `TEST FINISHED`または`TEST STOPPED`を確認。ファイル`Downloads\MakeCode_LimitLab\results\USER_UPLOAD_THIS_P171_STATUS.csv`をChatGPTに共有。

`labstatus171`で状態確認、`labstop171`で協調停止。ブロック操作が内部で固まった場合、即座の停止と終了通知は保証されない。ソース改変・破棄されたワールドの復旧や自動削除は行わない。

P1.7.1は**コードのオフライン試験とGitHub Actionsだけで検証**し、Minecraft Education実機ではまだ未検証。P1.7の今回の実機CSVをP1.7.1のPASSとして取り扱わない。ユーザーの実測CSVは公開GitHubにアップロードしない。既存のP1.0〜P1.7の検証済みソースは変更しない。
