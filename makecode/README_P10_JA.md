# MakeCode LimitLab P1.0 — 統合実験（Minecraft Education）

> **実機でのP1.0動作は未検証です。** TypeScript補助型の静的検査、オフラインのブロック模擬試験9件に合格。Minecraft Education専用ワールドでのみ使うこと。

## 何が統合されている？

| 工程 | 内容 | 通常モード `labauto1` |
| --- | --- | --- |
| 施工・第1段階 | 16×16×16=4096ブロック、fill/clone各2試行 | 実行 |
| 施工・第2段階 | 16×32×32=16384ブロック、fill/clone各1試行 | 第1段階成功時のみ実行 |
| 高速ブロック更新 | 16×16パネル、full/delta/clone各6フレーム | 施工が成功した場合だけ実行 |
| TXT入出力 | 1KB/64KB/256KB、読み戻して完全一致 | 施工が成功した場合だけ実行 |
| 安定性 | 約15秒の短時間チェック | 実行 |
| 長期安定性 | 約5分の停止可能な計算＋ログ更新 | `labsoak1`で別途実行 |

**重要：** `fill` と `clone` は共通の縞模様を生成し、施工後はコピー元との領域一致を比較。比較の公平性を高めるため、4096の2試行では `fill→clone` と `clone→fill` に順序を変える。コピー元の構築時間は本施工時間とは別のログに保存。施工命令単独の所要時間はWindowsファイル時刻差による**概算**で、正確なベンチマーク値や倍率ではない。

## あなたの操作（標準試験）

1. `COPY_CODE.cmd` をダブルクリックして `COPY OK` を確認。ログ用の `Downloads\MakeCode_LimitLab\logs` と結果用 `results` が作られる。ダウンロードフォルダ直下に結果ファイルは作成しない。
2. **新規・テスト専用**のスーパーフラットMinecraft Educationワールドを開く（P0.8と同じテストワールドでも可。ただし既存施設に重ならない場合のみ）。既存の実験が実行中なら終了まで待つ。
3. MakeCodeで `File Read & Write` 拡張機能が入っているのを確認し、JavaScript欄で `Ctrl+A` → `Ctrl+V`。エラーが0件なのを確認して緑の▶ボタンを押す。
4. Minecraftチャットに **`labauto1`** と1回入力する。`LimitLab P1 ALL PASS status CSV ready` または `STOP` が出るまで待つ（実時間は不明。進行状況はチャットに出る）。
5. `Downloads\MakeCode_LimitLab\results\USER_UPLOAD_THIS_P10_STATUS.csv` をアップロードする。**RUN_RESULTSは不要**。`OPEN_RESULTS.cmd` は結果フォルダを開くための任意ツール。

### 任意コマンド

- `labstatus1`：現在の処理段階を表示
- `labstop1`：停止要求（ブロック操作1命令の途中停止はできない）
- `labsoak1`：標準試験の全工程がPASSした後だけ、**約5分**の追加耐久試験を開始。完了すると同じCSVに追記。必須ではない。
- `labversion`：読み込まれているコードの確認

### 作業領域と安全対策

- ワールドへの変更があります。既存の建築物がある本番ワールドで実行しないこと。
- 起動時のプレイヤー座標を記録し、施工原点を `プレイヤーX+72 / プレイヤーY+8 / プレイヤーZ+12` とする。Minecraft内部で移動してもこの原点は変わらない。
- 施工原点からのオフセット（すべて整数座標）：
  - 4096 source：X=0..15、Y=0..15、Z=0..15。fill X=24..39、clone X=48..63。2回目の各施工先はZ=18..33。
  - 16384 source：X=0..15、Y=0..31、Z=42..73。fill X=24..39、clone X=48..63。
  - 更新試験：Z=82..97、Y=0、参照フレームX=0..15 / 24..39、表示X=48..63。
  - 空気参照：X=0..7、Y=45..52、Z=0..7。**これは変更しない**。
- 空気参照512ブロックを全件確認し、施工先は8×8×8に分けて領域全体を空気と照合。占有した領域では停止。施工先とコピー元は互いに離れており、意図せぬ上書きは避ける。施工前の検査がPASSでもプレイヤーや別プログラムがブロックを変更した場合は競合するため、実験中はほかの変更を行わない。
- 施工後に8×8×8タイルごとに比較して一致確認。検証失敗時はそこで停止。自動で消す・復元することは**しない**。途中までの構造物は残る場合がある。
- Minecraftのチャンクが未読み込みの場合、制限などで失敗する可能性がある。無条件に成功するものではない。

### 結果ファイル

- `USER_UPLOAD_THIS_P10_STATUS.csv`：各段階のPASS/FAIL・施工量・試行回数。これを送る。
- `logs/P10_*`：測定の開始・終了時刻をあとで調べるためのイベントファイルとデータ往復検証ファイル。
- `REVIEW_TIMINGS.cmd`：任意。Windowsでファイル時刻差を使った*概算*一覧 `results/P10_TIMING_ESTIMATES.csv` を生成。高精度計時ではないため、厳密な倍率の計算に使用しない。

### スケールに関する注意

- 4096／16384は研究目標として用いるブロック数で、現行MakeCode/Educationの実機制限を実測した値ではない。
- 標準実行で自動的に1MBファイルを作成することはしない。256KBの段階が実機で成功してから拡張を検討する（大容量文字列のメモリ負荷を避ける）。
- 標準の長時間試験は約15秒、5分間試験は任意。実際の経過時間はワールド状態・ゲーム負荷に影響される。

## 運用方針

- クラウドプロジェクト内でChat主体の開発。**WorkはChatより明確に効率がよい／Workでしかできないと判断した場合のみ、クラウドWorkを使用**。ローカルWorkは原則不使用。
- あなたの作業はコード貼付、1コマンド、時々の実機確認、CSV送付を基本とする。
- 既存MinecraftAIBuilderのコード／ワールドには手を触れない。
- ChatGPTプロジェクトやGitHubリポジトリの作成・公開は今回行っていない。
