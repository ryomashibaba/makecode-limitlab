# MakeCode LimitLab — P1.5 | 32,768ブロック分割施工の実機研究

## 今回の方向転換
P1.0 は 16,384 ブロックの fill/clone・256KiB ファイル往復を実機PASS。P1.3 は 300 回の短時間耐久を実機PASS。P1.4 は 512 ブロックの fill/clone 各4試行PASS、待機主体の PAUSE150 が非常に低速となり106/150で利用者が安全停止した。

**P1.5は長い待機試験を廃止**し、本来の研究目標である大きな空間の施工限界へ戻る。既存のP1.0〜P1.4ソースや成果CSVを上書き・公開しない。

## 今回の設計
- 対象：**32,768 = 16×32×64 ブロックの領域を3つ（コピー元、fill先、clone先）**。合計98,304ブロックを書き換える可能性があるため、必ず破棄可能な専用テストワールドで実施する。
- 開始前に、空気の基準領域512ブロックを全件確認。書き換える**3領域すべて**を8×8×8タイルで検査する。空きがなければ最大3候補の検索後、**一切施工せず中止**。
- コピー元：各層16×64=1,024ブロックの `fill` を32回。8×8×8の基準パターン512ブロックを全数検査し、コピー元64タイルの完全一致を確認する。
- fill先：各1,024ブロック×32命令。コピー元と8×8×8タイル×64箇所で完全一致検証。
- clone先：16×32×8=4,096ブロック×8命令。コピー元との完全一致を64タイル検証。
- 各区間を `CSV` に保存。長時間待機ループは**実装していない**。協調停止のため、ごく短い1ms待機チェックポイントのみを設ける。
- `labplan15` は、65,536ブロック分割案をチャットに表示するだけの読み取り専用機能。**65,536ブロック施工はまだ実装せずHOLD**。

**重要**：この試験はMinecraft自身の実際の `fill` / `clone` 1命令の上限を確定する試験ではない。分割で32,768ブロックを正しく構築・複製できるかが対象。成功しても「32,768ブロックを1命令で施工できた」と主張しない。また、実行時間の上限・完了時刻を保証する仕組みはない。遅くなれば `labstop15` を使い、再実行しない。

## 一度だけお願いするWindows・Minecraft操作
1. [GitHubから最新版ZIP](https://github.com/ryomashibaba/makecode-limitlab/archive/refs/heads/main.zip) を取得・解凍。**ZIPにはプロジェクト全体が入る**ので、P1.5には `makecode/` だけ使う。
2. `makecode/COPY_P15.cmd` を実行し、**COPY OK** の表示を確認する。失敗時は `PASTE_THIS_P15.ts` を開いて手動コピー（内容はハッシュと全文読み戻しをチェック済み）。
3. Minecraft Education のLimitLab専用テストワールドでMakeCodeに `Ctrl+A` → `Ctrl+V`。File Read & Write拡張機能が追加済みでエラー0件になったら再生。
4. チャットで `labauto15` を**1回だけ**実行する。空間を変更する。結果は `Downloads\MakeCode_LimitLab\results\USER_UPLOAD_THIS_P15_STATUS.csv`。
5. 結果CSVをこの会話へ添付。**新しいブロックを削除する機能はない。** 途中停止後の再実行も禁止。

## 状態確認・停止
- `labstatus15`：実行中の段階、進捗、理由を表示。
- `labstop15`：協調停止要求。次のチェックポイントで停止する。即時停止は保証されない。
- `labplan15`：読み取り専用の分割施工計画。施工しない。

**P1.5の実機成功は、このREADME作成時点では未確認**。GitHub ActionsのTypeScript+Minecraftスタブ・Nodeシミュレーション・Windows準備チェックは実機動作を保証しない。成功を判断する根拠は実機CSVのみ。

## 学習と品質
この実験は「分割して構築可能な規模」と「1命令あたりの上限」を厳密に区別する。P1.0/P1.4のファイル時刻由来の所要時間は精密ベンチマークではないため、速度倍率を断定しない。

開発はChat主体。Workはユーザーが許可し、明確な効率差がある場合のみ。既存MinecraftAIBuilder・他のワールドには触れない。
