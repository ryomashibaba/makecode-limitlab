# MakeCode LimitLab P2.2.1 — 起動無反応・計画停止・施工場所を修正

**実装およびオフラインCIを検証する修正版。Minecraft Education実機はまだ未検証です。P2.2実機成功の主張ではありません。**

## なぜP2.2.1が必要か

P2.2の`labfast22`実行後、ユーザーの画面では`labstatus22`を送っても応答が見えませんでした。P2.2は一回限りの記録を更新してから、**CPUで事前計算を完了するまでSTART表示を出さない**設計であり、計画中の譲り処理・状況報告もありませんでした。さらにユーザーはP2.1の試験済み使い捨てワールドから、周囲に建築物のない地点まで移動していました。

このため、無応答の原因が計算の占有かFile Read & Writeの遅延か実行停止かは確定できません。そこで**計画前から状況が分かる修正**を行い、推測だけでハードウェアの原因を断定しないようにします。旧P2.2の`P22_ONCE.txt`と結果ファイルをリセット・上書きしません。

## 修正箇所

| 処理 | P2.2 | P2.2.1 |
| --- | --- | --- |
| 起動通知 | ファイル確認＋計算後にSTART | **チャットコマンドを受信した瞬間にCOMMAND RECEIVED** |
| CPU事前計算中 | 表示・譲りなし | `PLAN 0/770`から進捗更新、定期的な短い`loops.pause(1)`、停止チェック |
| 停止時の記録 | 計画途中ではCSV開始行がないことがある | **RUN BEGIN/PLAN BEGINを計画前に保存**し、STOPを記録 |
| 施工場所 | 主要代表点・境界点のみ | **コピー元125＋複製先125＝250点のAIR調査を追加** |
| 施工座標の確認 | 表示コマンドなし | **`labarea221`で施工範囲を読取り専用で表示** |
| 実行記録とCSV | P22を使用 | **P221専用**。P22の停止・施工記録は保持 |
| 施工方法 | 68 SOURCE fill＋2 clone＋1 PATCH fill | **変えない**。速度優先、FASTとVERIFYも維持 |

事前計算の対象は**82×49×77＝309,386ブロック／領域**。SOURCEの計画は68回のfill、非AIR施工体積208,010、2回の大型clone、1回の16³パッチです。これらはオフラインの計画値であり、**実際のMinecraft実行時間の短縮は未確認**です。

## 重要：同じ使い捨てワールドでよいか

**新しく作った専用テストワールドが最も安全**です。ただし、P2.1で使った**破棄可能なLimitLab専用ワールドを再利用したい場合**、以前の建築物から十分離れ、施工予定の**コピー元・複製先・周辺の余裕・参照キューブ**がすべて空であることを自分で確認できるなら、試験目的で使えます。

**見た目が何もないだけでは完全な保証になりません。** 新設の250点チェックも全域ではなく、検査点にかからない既存ブロックを見逃すことがあります。P2.2.1では任意のワールドが使い捨てかどうかを自動識別できません。重要なワールド・都市建築中のワールド・MinecraftAIBuilderのワールドでFAST/VERIFYを実行してはいけません。

施工範囲はプレイヤーの現在位置から**X+16、Y+16、Z+24**を原点として計算されます。SOURCE 82×49×77、TARGETはさらにX+98から始まります。VERIFYは追加で8³の参照領域を3つ使用します。`labarea221`でワールド内の実座標を表示できます。**移動後にコマンドを実行した場合、施工座標も変わる**ため、その位置で確認してください。

## 操作手順

1. [GitHub mainのZIP](https://github.com/ryomashibaba/makecode-limitlab/archive/refs/heads/main.zip)を解凍して、`makecode/COPY_P221.cmd`をダブルクリック。`COPY OK`の表示を確認。
2. Minecraft EducationのMakeCode JavaScriptに貼り付け、**File Read & Write拡張機能**を維持して、エラー0件を確認します。
3. **破棄可能なLimitLab専用ワールド**で、必要なら先にチャットで **`labarea221`** を実行します。施工範囲を表示するだけで、ブロックもCSVも変更しません。
4. 通常の高速試験なら **`labfast221`** を一度だけ入力。詳しい全域一致検査を希望するときだけ、別の新規試験として **`labverify221`** を選択します（同じ実行記録の使い回しや途中切替は不可）。
5. 入力直後に **`COMMAND RECEIVED FAST`**、その後 **`WORKER ACTIVE`→`PLANNING`→`PLAN ...`→`SITE CHECK`→`SOURCE`→`CLONE`→`PATCH`** と進みます。どこまで到達したかを区別できます。
6. **`TEST FINISHED`または`TEST STOPPED`** 後、`Downloads\MakeCode_LimitLab\results\USER_UPLOAD_THIS_P221_STATUS.csv`をこの会話にアップロードしてください。

作業中は`labstatus221`で工程・進捗、`labstop221`で協調停止、`labreport221`で結果を再表示。通常これらの補助コマンドで再施工は始まりません。

**大きなMinecraftネイティブAPI命令の実行中に強制停止できる保証はありません。** たとえチャット応答が戻っても、既存のブロックの自動削除や復元は行いません。

## FASTとVERIFYの違い

- **FAST：`FAST_COMPLETED_SAMPLED`**。小数の代表点で確認した施工完了。全域完全一致ではありません。指定範囲外にないものや見逃したブロックも自動検出できません。
- **VERIFY：`VERIFY_PASS_EXACT`**。施工後にソースと部分変更済みターゲットを8³参照タイルで全域照合。**事前のAIRチェックだけはFASTと同じサンプル方式**なので、既存ワールド保護の保証にはなりません。

## トラブル時

- **COMMAND RECEIVEDが出ない**：MakeCode側のチャットイベントが実行されていない可能性があります。プログラムを繰り返し実行せず、現在の状態を共有してください。
- **COMMAND RECEIVEDのみ／WORKER ACTIVEで停止**：起動・ファイルI/Oやランタイムの問題が疑われます。何回も`labfast221`を送らないでください。
- **PLANの数字が増える**：事前計算中。停止は`labstop221`で要求可能。
- **SITE_NOT_AIR／SAMPLE_MISMATCH**：現在の予定領域にAIRでない場所が見つかっています。試験は自動再試行しません。
- **一回限りの記録で拒否**：`P221_ONCE.txt`を手で消さないでください。元のP22とP221の停止記録は保存します。

**この版の目的は応答性と安全な実機調査を回復することです。** 完了後の計測結果を踏まえ、次の巨大都市生成機能へ開発を進めます。
